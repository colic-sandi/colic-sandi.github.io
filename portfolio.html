LIBRARY v1.7 - Gestione Biblioteca

README

Progetto: LIBRARY v1.7 - Lezione 8 maggio 2026

Un'applicazione web completa per la gestione di una biblioteca comunale con sistema di prestiti online.

Descrizione

LIBRARY è un sistema integrato che permette:

  • Visualizzazione catalogo online di oltre 100 libri con immagini
  • Autenticazione sicura per utenti e amministratori
  • Gestione completa prestiti con 4 stati distinti
  • Calcolo automatico giorni di scadenza
  • Admin panel per gestione totale catalogo
  • Archiviazione immagini libri come BLOB database

Tecnologie Utilizzate

  • Backend: PHP 7.4+
  • Database: MySQL (2 database: library_auth, colic_db)
  • Frontend: HTML5, CSS3
  • Server: XAMPP (Apache)

Credenziali Test

  • Admin: admin / admin
  • Utente: test / test

Funzionalità Per Utenti

  • Visualizzare catalogo 50 libri per pagina
  • Ricerca per titolo e classificazione Dewey
  • Richiedere prestiti libri disponibili
  • Visualizzare prestiti attivi
  • Controllare giorni scadenza

Funzionalità Per Amministratori

  • Gestire catalogo (aggiunta, modifica, eliminazione)
  • Caricare immagini libri
  • Approvare/negare richieste prestito
  • Tracciare 4 stati prestito
  • Importare dati da JSON

Technical Report

Architettura Database

library_auth: Gestione utenti e prestiti

users: id, username (UNIQUE), email (UNIQUE), password (hash), role, created_at prestiti: id, user_id (FK), book_isbn, book_title, data_*, durata_giorni, stato (ENUM), created_at

colic_db: Catalogo libri ed editori

editori: id, nome, created_at libri: id, titolo, autore, anno_pubblicazione, isbn (UNIQUE), editore_id (FK), dewey_class, copie, immagine (LONGBLOB), created_at

Ciclo Vita Prestito

1. RICHIESTA: Utente richiede → stato="richiesta", copie rimangono uguali 2. CONFERMATO: Admin conferma → stato="confermato", copie-- 3. RITIRATO: Admin conferma ritiro → stato="ritirato", inizio conteggio giorni 4. RESTITUITO: Admin conferma restituzione → stato="restituito", copie++

Protezioni Sicurezza

  • XSS: Funzione h() per sanitizzare output
  • SQL Injection: Prepared statements con bind_param()
  • Password: password_hash() e password_verify()
  • Session: session_regenerate_id() dopo login
  • Authorization: check_admin() per pagine riservate

Competenze Dimostrate

  • Autenticazione e gestione sessioni
  • Design database relazionali
  • CRUD operations complete
  • Gestione file (JSON, BLOB)
  • HTML/CSS responsive
  • Logica business complessa
  • Best practices sicurezza

CRF Verification - Cross-Site Request Forgery

README

Progetto: CRF Verification System

Implementazione di meccanismi di protezione contro attacchi Cross-Site Request Forgery.

Descrizione

Un sistema che implementa token CSRF per proteggere le azioni critiche dell'applicazione.

Funzionalità

  • Generazione token CSRF univoci
  • Validazione token per richieste POST
  • Protezione form critiche
  • Gestione scadenza token

Technical Report

Cos'è CSRF

Cross-Site Request Forgery (CSRF) è un attacco che forza l'utente autenticato a eseguire azioni non volute su un'altra applicazione.

Implementazione

// Generazione token CSRF session_start(); if (empty($_SESSION['csrf_token'])) { $_SESSION['csrf_token'] = bin2hex(random_bytes(32)); } // Validazione token if ($_SERVER['REQUEST_METHOD'] === 'POST') { if (!hash_equals($_SESSION['csrf_token'], $_POST['csrf_token'] ?? '')) { die('CSRF token validation failed'); } }

Come Usare

  1. Generare token all'inizio della sessione
  2. Includerlo in ogni form come hidden field
  3. Validare il token per ogni richiesta POST
  4. Rigenerare token dopo login critico

Protezione Implementata

  • Token univoco per sessione
  • Validazione con hash_equals() (timing attack safe)
  • Rigenerazione token dopo azioni critiche
  • Scadenza token dopo timeout sessione

CRUD Operations - Create Read Update Delete

README

Progetto: CRUD Operations System

Implementazione completa di operazioni Create, Read, Update, Delete con validazione e sicurezza.

Descrizione

Un sistema per gestire dati con operazioni CRUD complete (Create, Read, Update, Delete).

Operazioni Implementate

  • CREATE: Inserimento nuovi record con validazione
  • READ: Lettura record con filtri e paginazione
  • UPDATE: Modifica record con validazione cambamenti
  • DELETE: Eliminazione record con conferma

Technical Report

Struttura Database

CREATE TABLE records ( id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY, name VARCHAR(255) NOT NULL, email VARCHAR(255) NOT NULL, phone VARCHAR(20), created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP );

CREATE - Inserimento Dati

$sql = "INSERT INTO records (name, email, phone) VALUES (?, ?, ?)"; $stmt = $conn->prepare($sql); $stmt->bind_param('sss', $name, $email, $phone); $stmt->execute();

READ - Lettura Dati

$sql = "SELECT * FROM records WHERE id = ?"; $stmt = $conn->prepare($sql); $stmt->bind_param('i', $id); $stmt->execute(); $result = $stmt->get_result(); $record = $result->fetch_assoc();

UPDATE - Modifica Dati

$sql = "UPDATE records SET name = ?, email = ?, phone = ? WHERE id = ?"; $stmt = $conn->prepare($sql); $stmt->bind_param('sssi', $name, $email, $phone, $id); $stmt->execute();

DELETE - Eliminazione Dati

$sql = "DELETE FROM records WHERE id = ?"; $stmt = $conn->prepare($sql); $stmt->bind_param('i', $id); $stmt->execute();

Protezioni Implementate

  • Prepared statements per tutte le query
  • Validazione input su CREATE e UPDATE
  • Protezione XSS con h() function
  • Gestione errori completa
  • Conferma prima DELETE

Auth System - Sistema Autenticazione

README

Progetto: Auth System - Autenticazione Sicura

Implementazione completa di sistema autenticazione con gestione sessioni e password hashing.

Descrizione

Un sistema di autenticazione professionale con login, registrazione e gestione sessioni sicure.

Funzionalità

  • Registrazione utenti con validazione
  • Login con email o username
  • Password hashing con password_hash()
  • Gestione sessioni sicure
  • Logout con distruzione sessione
  • Remember me (optional)
  • Reset password

Technical Report

Schema Database

users table: - id (PK) - username (UNIQUE) - email (UNIQUE) - password (hash) - role (user/admin) - is_active (boolean) - created_at, updated_at

Password Hashing

// Hashing password $password_hash = password_hash($password, PASSWORD_DEFAULT); // Verifying password if (password_verify($password, $password_hash)) { // Password correct }

Session Management

// Login session_start(); session_regenerate_id(true); $_SESSION['user_id'] = $user['id']; $_SESSION['username'] = $user['username']; $_SESSION['role'] = $user['role']; // Logout session_destroy();

Protezioni Sicurezza

  • Password: password_hash() bcrypt hashing
  • Session: session_regenerate_id() dopo login
  • CSRF: Token CSRF su form login
  • XSS: Sanitizzazione output
  • Brute Force: Limitazione tentativi login
  • Email: Validazione formato email
  • Password: Requisiti minimo 8 caratteri

Validazione Registrazione

  • Username: 3-50 caratteri, alfanumerici
  • Email: Formato valido, UNIQUE nel database
  • Password: Minimo 8 caratteri, 1 maiuscola, 1 numero
  • Conferma password: Match con password

Validazione Login

  • Username/Email: Obbligatorio
  • Password: Obbligatoria
  • Verifica credenziali nel database
  • Controllo utente attivo (is_active)
